# Five-minute demo

0:00–0:30 — Explain the problem: disconnected college data delays targeted support.
Show separate college/role access and say all demo records are fictional.

0:30–1:15 — Open Success Intelligence. Explain seven categories and the unified
student ID. Show branch, period and segment filters, trend and coverage.

1:15–2:00 — Search DEMO0001. Show score 68 and all component contributions. Strong
academics but weak placement is the key insight: marks alone would miss this student.
Explain placement and coding triggers. Show source dates and recommended support.

2:00–2:45 — Create a coding-practice support action with mentor and due date.
Mark reviewed after showing the stored action. Run the marks +10 what-if and
explain that it does not edit student data or guarantee improvement.

2:45–3:20 — Show DEMO0005 with insufficient score coverage and DEMO0007 with a
feedback request. Missing data is not zero performance; asking for help is not penalized.

3:20–4:00 — Train synthetic demonstration model. Show holdout metrics and predictions.
Explicitly say metrics reflect simulated labels, not real-world accuracy. Historical
outcomes and prospective validation are needed before operational prediction.

4:00–5:00 — Show Faculty & Subjects, explain faculty marks/attendance → student
views → unified score, and describe Supabase persistence. Finish with limitations:
human review, logical tenant isolation, no proven causal intervention effect.

Alternative real-data demo: use the provided CSV templates and the institution's
approved anonymized data. Replace roll numbers consistently across all sources.
